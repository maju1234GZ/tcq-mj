# 提词器 App · 交接说明

> 版本 v1.0.0 ｜ 2026-10-22 初版交付
> 安卓真悬浮窗（可叠在抖音录制界面上）+ iOS App内录制，语音跟读自动滚动，透明底白字（颜色可调）。

---

## 一、功能与实现

| 能力 | 安卓 | iOS |
|---|---|---|
| 提词悬浮在抖音等App之上 | ✅ 系统悬浮窗（WindowManager 前台服务） | ❌ iOS系统禁止，改为App内录制 |
| App内录制（相机+提词同屏） | 有（web预览模式） | ✅ 前置相机+提词叠加，成片自动存相册 |
| 语音跟读滚动 | ✅ 系统SpeechRecognizer（免费离线） | ✅ SFSpeechRecognizer |
| 云端ASR（自有服务器） | ✅ WebSocket PCM流 | ✅ 同左 |
| 透明底/字体颜色/字号/行距/速度 | ✅ 悬浮窗内实时调 | ✅ 页面实时调 |
| 悬浮窗内按钮 | 播放/暂停/加速/减速/关闭/拖动/缩放 | — |

语音识别双通道在「设置」页切换；云端地址存 `tp_server_url`。
跟读算法（尾30字锚点+120字窗口模糊匹配+只前进不回滚）在 JS 与 Kotlin 各一份，见 `docs/插件接口契约.md` 第五节。

## 三、本机环境（刚装好）

- **Node.js v22.17.0 便携版**：`E:\软件\nodejs`（已加用户 PATH，重装系统只需重加 PATH）
- npm 已切 npmmirror 镜像
- 本机无 JDK/Android SDK/Xcode——**双端打包全部走 GitHub Actions 云构建**

## 四、出包流程（云端）

1. 代码推到 GitHub（新建私有仓库，如 `teleprompter`）：
   ```powershell
   cd E:\提词器
   git init; git add -A; git commit -m "v1.0.0"
   git remote add origin <你的仓库地址>
   git push -u origin main
   ```
2. GitHub 仓库页 → Actions：
   - **Android APK 云构建**：push main 自动跑；或手动 Run workflow。产物 `提词器-debug-x.x.x.apk` 可直接装手机（debug 包免签名）。
   - **iOS 未签名 IPA 云构建**：仅手动触发。产物未签名 IPA，需用爱思助手/AltStore 自签后安装（7天有效），或后续配 688元/年 开发者证书。

## 五、云端ASR服务端部署（自有服务器）

```bash
cd server-asr
pip install -r requirements.txt    # torch CPU 版即可，首次下模型约1GB
python asr_server.py               # 监听 ws://0.0.0.0:8765/ws
```
然后在 App「设置 → 语音源 → 云端ASR」填 `ws://服务器IP:8765/ws`。
协议见契约第四节；text 始终为累计全文，与系统识别语义一致。

## 六、首次使用顺序（安卓）

1. 装 debug APK → 打开 App → 台本列表 → 新建台本粘贴台词
2. 点「开拍」→ 首次会引导授权：悬浮窗权限 + 麦克风权限
3. 悬浮窗出现后切到抖音开始录制，说话即跟读滚动；悬浮窗上可直接调速度/暂停/关闭

## 七、已知风险（云构建首次可能报错点，按概率排序）

1. iOS `project.pbxproj` 手工插入的文件引用——若 xcodebuild 报工程解析错误，优先查这里
2. iOS 用了 iOS17 API（AVAudioApplication 等），CI runner 必须 Xcode 15+（workflow 已指定 macos-15）
3. Android okio 版本若被传递依赖降级，`toByteString` 编译失败（已显式声明 okhttp 4.12.0 规避）
4. 悬浮窗在部分国产 ROM（小米/华为）还需额外开「后台弹出界面」权限——真机测试时注意
