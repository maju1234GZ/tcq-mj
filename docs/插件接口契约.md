# Teleprompter 原生插件接口契约

插件名：`Teleprompter`，前端通过 `src/teleprompter.js` 调用。
Android 与 iOS 双端必须实现完全一致的方法签名与事件名。

## 一、数据类型

### PrompterStyle（提词样式）
| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| text | string | 必填 | 完整台本文本（纯文本，\n 分行） |
| fontSize | number | 34 | 字号（Android: sp / iOS: pt） |
| color | string | "#FFFFFF" | 字体颜色 hex，如 #FFFFFF #00FF88 |
| bgOpacity | number | 0.35 | 背景不透明度 0~1（0=全透明） |
| lineSpacing | number | 1.4 | 行距倍数 |
| speed | number | 40 | 定速模式滚动速度（像素/秒，逻辑像素） |
| mode | string | "voice" | "voice" 语音跟读 / "timed" 定速滚动 |
| mirror | boolean | false | 是否镜像显示（预留，v1 可不实现） |

### SpeechOptions（语音识别）
| 字段 | 类型 | 说明 |
|---|---|---|
| source | string | "system"=系统识别 / "cloud"=云端ASR |
| serverUrl | string | source=cloud 时必填，如 ws://1.2.3.4:8765/ws |
| lang | string | 默认 "zh-CN" |

## 二、方法

### 权限
- `hasPermissions() => Promise<{ overlay: boolean, mic: boolean, camera: boolean }>`
  - Android: overlay=悬浮窗权限；iOS: overlay 恒为 true
- `requestPermissions() => Promise<{ overlay: boolean, mic: boolean, camera: boolean }>`
  - Android: 跳系统悬浮窗授权页 + 申请录音权限；iOS: 申请麦克风/相机/语音识别权限

### Android 悬浮窗（iOS 调用为空实现，直接 resolve）
- `startOverlay(style: PrompterStyle) => Promise<void>` 启动悬浮窗并开始提词
- `updateOverlay(style: Partial<PrompterStyle>) => Promise<void>` 实时更新样式/文本/速度
- `stopOverlay() => Promise<void>` 关闭悬浮窗并停止识别
- `getOverlayState() => Promise<{ running: boolean, position: number }>` position=当前滚动到的字符索引

### 语音识别（双端共用；Android 在悬浮窗运行期间由原生内部使用，JS 也可独立调用）
- `startSpeech(opts: SpeechOptions) => Promise<void>`
- `stopSpeech() => Promise<void>`

### iOS App内相机（Android 调用为空实现）
- `startCamera(opts: { position: "front" | "back" }) => Promise<void>` 相机预览渲染在 WebView 透明背景之下
- `stopCamera() => Promise<void>`
- `startRecording() => Promise<void>`
- `stopRecording() => Promise<{ saved: boolean }>` 停止并保存到系统相册

## 三、事件（addListener）

| 事件名 | 载荷 | 说明 |
|---|---|---|
| `speech` | `{ text: string, isFinal: boolean }` | 识别结果（增量/全量由原生保证为"当前已识别全文"） |
| `overlayEvent` | `{ action: string, position?: number }` | 悬浮窗内按钮事件：play/pause/close/seek |
| `recordEvent` | `{ action: "saved" | "failed", message?: string }` | iOS 录制结果 |

## 四、云端ASR WebSocket 协议（server-asr 服务端与双端原生共同遵守）

- 连接：`ws://host:8765/ws`
- 客户端 → 服务端：
  - 首帧 JSON 文本：`{"type":"config","lang":"zh-CN","sampleRate":16000}`
  - 后续二进制帧：PCM 16bit 16kHz 单声道音频块
  - 结束 JSON 文本：`{"type":"end"}`
- 服务端 → 客户端（均为 JSON 文本帧）：
  - `{"type":"partial","text":"当前已识别全文"}` 中间结果
  - `{"type":"final","text":"当前已识别全文"}` 一句话结束
  - `{"type":"error","message":"..."}`
- 语义：text 始终为**自 startSpeech 以来的累计全文**，与系统识别事件语义一致，滚动匹配逻辑双通道复用。

## 五、语音跟读滚动匹配算法（Android Kotlin 与前端 JS 各实现一份，逻辑一致）

1. 归一化：去除标点、空白、转小写（中文按字）。
2. 维护 `currentIndex`（已滚到的字符索引，初始 0）。
3. 每次收到识别全文 `text`，取其归一化后的**尾部最多 30 字**作为锚点 `anchor`。
4. 在台本归一化文本的 `[currentIndex, currentIndex + 120]` 窗口内，找 `anchor` 的最长公共后缀匹配位置（允许 1~2 字编辑距离的模糊匹配）。
5. 匹配成功且新位置 > currentIndex：平滑滚动到新位置（高亮线居中），currentIndex 更新。
6. 匹配失败：保持原位不动（不回滚，防止跳变）。
